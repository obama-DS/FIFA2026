## 2. Per-dataset report

### 2.1 E0 match files: `E0 (1).csv` ... `E0 (8).csv`, `E0.csv`

Standard Football-Data.co.uk "E0" (English Premier League) format.

- **What it contains**: one row per match. Full-time and half-time scorelines and results,
  referee, in-match team statistics (shots, fouls, corners, cards), and pre-match / closing
  betting odds from many bookmakers.
- **Useful columns**:
  - Identity: `Div`, `Date`, `Time`, `HomeTeam`, `AwayTeam`, `Referee`
  - Outcome: `FTHG`, `FTAG`, `FTR` (full-time goals and result H/D/A), `HTHG`, `HTAG`, `HTR`
  - Performance: `HS`, `AS`, `HST`, `AST`, `HF`, `AF`, `HC`, `AC`, `HY`, `AY`, `HR`, `AR`
  - Odds (keep stored but DO NOT use as model features unless requested):
    `B365H/D/A`, `BWH/D/A`, `PSH/D/A`, `WHH/D/A`, `Max*/Avg*`, over/under `>2.5/<2.5`,
    Asian handicap `AHh`, closing odds `*CH/*CD/*CA`, etc.
- **Likely key**: composite `(Date, HomeTeam, AwayTeam)`. No single column is unique.
- **Relationships**: share an identical schema, so they stack into one long table with a
  derived `Season` column. Team names link to `Squad` in the player file and to
  `Home Team`/`Away Team` in the fixtures file (see name mapping in section 3).
- **Possible problems**:
  - Column set differs by season (62, 106, 120, 132 columns). The extra columns are
    bookmaker odds, which are not needed for modelling anyway.
  - Season is not stored in the file; it must be derived from `Date` or from the file name.
  - Some odds columns have many missing values (e.g. `IWH` 182 missing in 2023/24,
    `PSH` 170 missing in 2025/26). Missing odds are harmless for this project.
  - `E0 (7).csv` and `E0 (8).csv` are byte-identical duplicates (same MD5). Keep one.
- **Recommendation**: **KEEP and TRANSFORM**. Concatenate all seasons into one `matches`
  table with a `Season` column, keep the core stats columns, drop odds for modelling.

### 2.2 `epl-2026-GMTStandardTime.csv`

- **What it contains**: the full 2026/27 Premier League fixture list: 380 rows (38 rounds
  x 10 games), each with `Match Number`, `Round Number`, `Date` (kickoff), `Location`
  (stadium), `Home Team`, `Away Team`, and an empty `Result` column.
- **Useful columns**: all except `Result` (which is the target to be forecast).
- **Likely key**: `Match Number` (unique single-column key).
- **Relationships**: this is the prediction target dataset. Team names must be normalised
  to match the historical E0 files (`Man Utd` -> `Man United`, `Spurs` -> `Tottenham`,
  `Nott'm Forest` matches already, and `Coventry`, `Hull`, `Sunderland`, `Leeds` are teams
  whose history is only partially in the 2018-2026 window).
- **Possible problems**: team-name conventions differ from the E0 files. Newly promoted
  teams may have little historical data in the window.
- **Recommendation**: **KEEP and TRANSFORM**. Add a `Season` column, standardise team
  names, keep `Result` as an empty target column for forecasting.

### 2.3 `players_data_light-2025_2026.csv`

- **What it contains**: per-player season statistics for 2025/26 scraped from FBref in the
  "light" (reduced-column) format. 1986 rows and 165 columns, but it is NOT only
  Premier League: it mixes the top-5 leagues (`Comp` = eng Premier League, es La Liga,
  it Serie A, fr Ligue 1, de Bundesliga). Only 404 of 1986 rows are Premier League players
  (20 EPL squads). 96 squads in total.
- **Useful columns**:
  - Identity: `Player`, `Nation`, `Pos`, `Squad`, `Comp`, `Age`, `Born`, `Rk`
  - Playing time: `MP`, `Starts`, `Min`, `90s`
  - Performance groups (full glossary in section 4): standard scoring (`Gls`, `Ast`,
    `xG`, `xAG`, ...), progressive (`PrgC/PrgP/PrgR`), shooting, passing, passing types,
    defense, SCA/GCA, possession, misc, goalkeeping.
- **Likely key**: composite `(Player, Squad, Comp)`. `Rk` is unique only within this file
  and is a table-rank, not a stable player ID.
- **Relationships**: `Squad` links to `HomeTeam`/`AwayTeam` in the E0 files and to
  `Home Team`/`Away Team` in the fixtures (requires name mapping, e.g.
  `Manchester Utd` <-> `Man United`).
- **Possible problems**:
  - No explicit `Season` column (implied only by the file name).
  - No permanent player ID; players who change clubs across seasons cannot be tracked
    reliably without a name-based mapping.
  - Multi-league content: training on all 5 leagues mixes different competitive levels.
  - Per-90 columns already exist, so raw per-90 computations are duplicated.
  - Only one season of player data (2025/26), while match data covers 2018/19-2025/26.
  - Goalkeeper-only columns are missing for almost all rows (expected).
- **Recommendation**: **KEEP and TRANSFORM**. Filter to `eng Premier League` for PL work,
  add a `Season` column, keep the per-90 stats, and treat `(Player, Squad, Season)` as
  the entity key.

### 2.4 `E3.csv`

- **What it contains**: 1997/98 League Two (Division `E3`) match results. 552 rows
  (a full 46-game season for 24 teams) but only the basic columns (`Div`, `Date`,
  `HomeTeam`, `AwayTeam`, `FTHG`, `FTAG`, `FTR`) are populated; 21 betting columns are
  completely empty.
- **Likely key**: composite `(Date, HomeTeam, AwayTeam)`.
- **Recommendation**: **IGNORE** for this project. It is not Premier League data, it is
  out of the required 2018/19-2025/26 window, and it is a different division.

### 2.5 `logs_0.csv`

- **What it contains**: a 14-row system/API log (timestamps + event name `setImApi`).
- **Recommendation**: **IGNORE**. Not football data.

## 3. Entity (team name) relationships

The three sources use different team-name conventions. A normalisation map is required
before joining. Observed mismatches:

| Player file (`Squad`) | E0 match files (`HomeTeam`/`AwayTeam`) | 2026/27 fixtures |
|---|---|---|
| Leeds United | Leeds | Leeds |
| Manchester Utd | Man United | Man Utd |
| Newcastle Utd | Newcastle | Newcastle |
| Nott'ham Forest | Nott'm Forest | Nott'm Forest |
| Tottenham | Tottenham | Spurs |
| Wolves | Wolves | (Wolves) |
| - | - | Coventry, Hull (no E0 history in window) |

Join plan:

- `matches` (E0 files stacked, 2018/19-2025/26) is the training table.
- `players_data_light-2025_2026.csv` (filtered to EPL) is the player-level feature table,
  joined on `Squad` + `Season`.
- `epl-2026-GMTStandardTime.csv` is the prediction table; `Result` is the target.
- Odds columns are excluded from features (per project rule).
- Fixture `Date` and historical `Date` share the same column name but represent different
  seasons; they must not be joined on `Date`.

## 5. Global data-quality notes

1. **No data was invented or modified.** Everything above comes from the raw files.
2. **Duplicate files**: `E0 (7).csv` and `E0 (8).csv` are identical; keep one.
3. **Season is not a stored column** anywhere; it must be derived from `Date` or filenames.
4. **Team-name normalisation** is required before any join (section 3).
5. **Betting odds** are present in all E0 files but are excluded from model features
   unless requested.
6. **Leakage caution**: player 2025/26 stats are end-of-season values. When forecasting
   2026/27, only historical seasons (2018/19-2025/26) should be used to build features;
   the current-season player file must not be used as input for 2026/27 targets.
7. **`play_df.py` + `premier_league_player_model.pkl`** (already in the project): an
   existing RandomForest training script and saved model. It trains on all 5 leagues and
   builds a `Performance_Score` from end-of-season stats, so it is not used as-is here
   (no new model training is performed in this phase).
8. File `players_data_light-2025_2026.csv` is UTF-8 with accented characters; when
   printing to a Windows console they may appear garbled, but the underlying data is fine.
