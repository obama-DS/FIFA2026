================================================================================
KEY FEATURES IMPLEMENTED
================================================================================

1. GAMEWEEK DETECTION
   - Automatically detects current gameweek from any reference date
   - Handles pre-season, mid-season, and post-season scenarios
   - Accounts for fixtures in progress (some started, some not)
   - Returns appropriate gameweek for "between gameweeks" scenarios

2. FIXTURE GROUPING
   - Groups all fixtures by round_number (gameweek)
   - Sorts fixtures chronologically within gameweek
   - Returns clean pandas DataFrame for easy processing

3. DEADLINE MANAGEMENT
   - Calculates deadline as first kickoff time in gameweek
   - Provides deadline checking against any reference date
   - Used for prediction locking and user guidance

4. FIXTURE STATUS TRACKING
   - Upcoming: Before kickoff time
   - Live: During match (kickoff to +2 hours)
   - Completed: Has result recorded
   - Postponed: Kickoff passed but no result (safe handling)

5. FEATURED FIXTURE SELECTION
   - Selects first kickoff match chronologically
   - Creates urgency and focal point for users
   - Handles simultaneous kickoffs with consistent tiebreaker

6. AI PREDICTIONS
   - Single fixture prediction with fixture_id
   - Batch predictions for entire gameweek
   - Optional probability calculations (win/draw/loss)
   - Optional SHAP explanations (supporting/opposing factors)
   - Lazy loading of prediction engines (efficient initialization)

7. PREDICTION LOCKING
   - locked_only parameter enforces deadline-based access
   - Returns empty list if deadline not passed (prevents early access)
   - Allows unlocked access for testing and preview
   - Crucial for "Beat the AI" game integrity

8. GAMEWEEK SUMMARIES
   - Comprehensive gameweek information dictionary
   - Human-readable print format
   - Includes deadline, status counts, featured fixture
   - Shows first/last kickoff dates

================================================================================
TECHNICAL ARCHITECTURE
================================================================================

CLASS: GameweekEngine

DEPENDENCIES:
- Fixtures CSV (data/master/fixtures_2026_27.csv)
- Features CSV (data/features/match_features.csv)
- Trained models (models/ directory)
- MatchProbabilityEngine (Phase 18)
- MatchExplainer (Phase 19)

INTEGRATION PATTERN:
- Reuses existing model_loader.load_best_models()
- Lazy loads MatchProbabilityEngine (only when probabilities requested)
- Lazy loads MatchExplainer (only when explanations requested)
- No duplicate ML logic
- No hardcoded fixtures or predictions

KEY METHODS:

1. get_current_gameweek(reference_date) -> int
   - Detects current gameweek from date

2. get_gameweek_fixtures(gameweek) -> DataFrame
   - Returns all fixtures for gameweek

3. get_gameweek_deadline(gameweek) -> datetime
   - Returns first kickoff time

4. is_deadline_passed(gameweek, reference_date) -> bool
   - Checks if deadline passed

5. get_fixture_status(fixture_id, reference_date) -> str
   - Returns 'upcoming', 'live', 'completed', or 'postponed'

6. get_featured_fixture(gameweek) -> dict
   - Selects featured match

7. get_fixture_prediction(fixture_id, include_probabilities, include_explanation) -> dict
   - AI prediction for single fixture

8. get_gameweek_predictions(gameweek, include_probabilities, include_explanations, locked_only) -> list
   - Batch predictions with optional locking

9. get_gameweek_summary(gameweek, reference_date) -> dict
   - Comprehensive gameweek info

10. print_gameweek_summary(gameweek, reference_date)
    - Human-readable summary output

================================================================================
DESIGN DECISIONS
================================================================================

1. SINGLE ENGINE CLASS vs SEPARATE CLASSES
   Chosen: Single GameweekEngine class
   Reason: Simplifies integration, avoids circular dependencies
   
2. GAMEWEEK DETECTION LOGIC
   Chosen: Use round_number from fixtures CSV
   Reason: Data already has gameweeks, no need to recalculate
   
3. DEADLINE CALCULATION
   Chosen: First kickoff time in gameweek
   Reason: Creates urgency, standard FPL pattern
   
4. FEATURED FIXTURE SELECTION
   Chosen: First kickoff match
   Reason: Simple, consistent, creates urgency
   
5. PREDICTION LOCKING
   Chosen: locked_only parameter returns empty list if not locked
   Reason: Clean API, prevents accidental early access
   
6. LAZY LOADING
   Chosen: Initialize prediction engines only when needed
   Reason: Fast startup for simple operations, efficient memory

7. FIXTURE STATUS LOGIC
   Chosen: 4 states (upcoming/live/completed/postponed)
   Reason: Handles real-world scenarios safely

USAGE EXAMPLES

EXAMPLE 1: Get Current Gameweek
```python
from src.gameweek import GameweekEngine

engine = GameweekEngine(
    fixtures_path="data/master/fixtures_2026_27.csv",
    features_path="data/features/match_features.csv",
    models_dir="models/"
)

current_gw = engine.get_current_gameweek()
print(f"Current gameweek: {current_gw}")
```

EXAMPLE 2: Get Gameweek Predictions
```python
predictions = engine.get_gameweek_predictions(
    gameweek=5,
    include_probabilities=True,
    include_explanations=False,
    locked_only=False
)

for pred in predictions:
    print(f"{pred['home_team']} vs {pred['away_team']}")
    print(f"Prediction: {pred['predicted_home_goals']:.1f} - {pred['predicted_away_goals']:.1f}")
    print(f"Win probability: {pred['home_win_probability']:.1%}")
```

EXAMPLE 3: Check if Predictions are Locked
```python
from datetime import datetime

# Check deadline
deadline = engine.get_gameweek_deadline(5)
is_locked = engine.is_deadline_passed(5)

if is_locked:
    # Get locked predictions
    predictions = engine.get_gameweek_predictions(5, locked_only=True)
else:
    print("Deadline not passed yet")
```

EXAMPLE 4: Get Featured Fixture

KNOWN LIMITATIONS
================================================================================

1. PowerShell execution issues (system-level, not code issue)
   - Cannot run Python tests via PowerShell (exit code 1)

   - Tests will run in Python environments

2. Match duration assumption

   - Real matches may vary (extra time, delays)
   - Does not affect core functionality

3. Postponed fixture handling
   - Cannot automatically detect rescheduled dates
   - Relies on fixture CSV being updated
   - Status will show "postponed" correctly

4. Feature availability
   - Requires features to exist in match_features.csv
   - Will skip fixtures without features (with warning)
   - Expected behavior for early-season predictions
